Mod Settings startup failure: independent forensic record
========================================================

Date: 2026-10-25. Target: Cyberpunk 2077 2.50 / 3.0.88.46235,
RED4ext 1.31.0, ModSettings-0.2.21-game2.5.

Finding
-------
The new Mod Settings source port omits native RTTI registration when built
with Clang. Its RedLib declaration macros do not require the inline static
ClassDefinition/ClassExpansion registrar members to be instantiated. The
installed DLL consequently never registers its seven native classes or the
inkActionName.ToName extension. Scripts compile, but the game's subsequent
native-definition validation fails. RED4ext's validation hook displays the
failure and calls TerminateProcess(GetCurrentProcess(), 1).

This explains the recorded 03:05:39 startup attempt. It is a defect in our
source port. The user confirmed that only the new game2.5 package was enabled;
the old v0.2.21 binary's callback-layout defect is a separate investigation.
The earlier 03:04 log alone did not identify a faulting instruction. Do not
assign an exception address or claim a matching minidump was recovered.

Source-to-binary explanation
----------------------------
1. Main.cpp calls Red::TypeInfoRegistrar::RegisterDiscovered() after installing
   hooks and registering the scripts. The call is present; adding it again
   would not populate the missing discovery queues.

2. The seven class declarations are in ModSettings.cpp and ModConfigVar.hpp;
   ActionNameEx.hpp declares the extension. The baseline generated RedLib
   include/Red/TypeInfo/Macros/Definition.hpp specializes TypeInfoBuilder but
   never references ClassDefinition<T>::s_registrar or the corresponding
   ClassExpansion registrar. Those inline static template members contain
   the constructor side effects that append registration/description callbacks.

3. llvm-nm --demangle on the captured Main.cpp.obj and ModSettings.cpp.obj
   finds the discovery callback vectors but no s_registrar, ClassDefinition
   or ClassExpansion symbols. The original PDB's public-symbol dump also
   contains none of those registrars. The installed DLL contains none of the
   seven complete NUL-terminated RTTI class names or the ToName method name.
   String absence is supporting evidence; the source, object symbols and
   runtime validation errors together establish the defect. The absence in
   compiler output also rules out explaining this solely as linker stripping.

4. The existing Codeware port already accounts for this compiler behavior in
   sources/codeware/lib/Red/TypeInfo/Macros/Definition.hpp. It takes the address
   of each declaration's registrar in a used variable, requiring instantiation
   and preserving that reference under the Windows linker. That adaptation
   was missing from Mod Settings' independent RedLib overlay.

5. sources/red4ext/src/dll/Hooks/ValidateScripts.cpp records each native
   validation error, builds the failure message and invokes
   SHOW_MESSAGE_BOX_AND_EXIT_FILE_LINE. Its definition in Utils.hpp calls
   TerminateProcess(GetCurrentProcess(), 1) after the message box. These
   observed errors therefore lead to an intentional startup termination;
   a native access-violation minidump is not needed to explain this attempt.

Compiler references, checked 2026-10-25:
  https://eel.is/c++draft/temp.inst#3
  https://eel.is/c++draft/temp.inst#4
  Class-template instantiation does not itself instantiate static member
  definitions; a member's initialization side effects require an actual use
  that needs its definition.
  https://clang.llvm.org/docs/AttributeReference.html#used
  Clang's used attribute requires emission and prevents linker section
  garbage collection on COFF. The ELF behavior is different and is not the
  relevant target here.

Validation gap and correction
-----------------------------
The preexisting native regression constructed TypeInfoRegistrar explicitly.
It tested copying/invoking the retail-sized callbacks and transactional hook
lifecycle, but bypassed the real declaration macros. The separate redscript
compile validated script syntax/type declarations, without an engine RTTI
registry to verify their native implementations. Both could pass with this
DLL defect present.

A separate user-confirmed session is implementing the correction and extending
the regression. During this investigation its actual-macro, multiple-translation-
unit probe produced:
  FAIL: declared RTTI classes and expansions discovered exactly once across translation units
That negative result and its probe sources were copied into the local evidence
directory. This investigation did not author or run that other session's test,
and does not claim its pending fix or rebuilt package has passed a game test.

The correction belongs in the managed Mod Settings RedLib overlay: explicitly
instantiate/preserve registrars for declarations and expansions, export the
overlay through scripts/mod_settings.py, and rebuild the Mod Settings package.
Validation must exercise the actual declaration macros, including one-time
registration when a header is included by multiple translation units. Inspect
the rebuilt DLL for the seven class registrars and extension, then perform a
separately authorized game startup test to check native validation and later
settings behavior. No compatibility shim is needed to correct this source-
port registration defect.

Scope
-----
Only local forensic evidence and this report were written by this investigation.
No game/MO2 files were changed, no game was launched, and no Git state was
mutated. Concurrent source/test changes belong to the other active session.
The known ArchiveXL journal-hook limitation and CET tweakdbstr load error are
not explanations for the demonstrated missing Mod Settings registrations;
their independent runtime effects are outside this finding.
