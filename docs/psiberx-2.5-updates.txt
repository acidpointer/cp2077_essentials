All three upstream releases advertise game patch 2.5 compatibility. ArchiveXL
also reports a fix for a potential crash when patching .ent resources. Its
new mesh validation, localization handling and extension-service integration
are retained. Source inspection and address presence do not establish runtime
compatibility with this project's shared, patched SDK.

Migration and patch review:
* The old working contents matched their saved stacks before migration.
  Backups and per-layer source trees are retained locally under
  build/mod-updates-20261025/. Existing CET edits were preserved.
* Each compatibility, SDK cleanup and attachment-lock layer was rebased
  separately and regenerated with scripts/patches.py export. No layer was
  collapsed; exporter reconstruction and checksums cover the new base.
* Upstream now supplies most address/layout and script-import changes. Those
  duplicate local changes disappear from the compatibility layers. Original
  community-port attribution remains in patches/README.md and lock provenance.
* Codeware keeps its local native callback signature adaptations and fallback
  vanilla API reconciliation. Upstream alias/function replacement and dynamic
  getter parameter handling are retained. The duplicate local script overloads
  for CallbackSystemHandler.SetRunMode/SetLifetime were removed in favor of the
  upstream bridges. Native script/input offset assertions remain real Clang
  static_assert checks. Public redscript ERTTIType naming and checked UTF
  conversion remain in the separate SDK cleanup layer.
* TweakXL takes its updated upstream data files and hashes. Its local metadata
  export bounds check remains, together with the separate RTTI/YAML cleanup.
* ArchiveXL's new single-writer thread-local skip workaround overlaps our
  existing attachment-lock layer. The final layer replaces that workaround
  with the existing three owner-scoped writer routes and protected snapshots;
  it retains listener lifetime management and hook rollback. The upstream
  workaround is not installed alongside those hooks.
* ArchiveXL retains its previous cooked-node element-edit limits, node lookup
  guard, 0x30 ResourceRequest layout and safe missing-address resolver.
  JournalTree_ProcessJournalIndex and ResourceLoader_OnUpdate keep their
  previously unavailable hashes: journal indexing and resource hot reload
  remain disabled. No new addresses were guessed or claimed as fixes.
* The shared SDK and unrelated mod/dependency pins are unchanged. The vendor
  SDK Gitlinks contained in the new upstream commits are not initialized or
  used by this build; all three targets still consume sources/red4ext-sdk.
